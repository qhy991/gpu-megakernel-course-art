# Lesson 12 ImageGen prompt

Purpose: create a beginner teaching image for the exact-binary evidence chain from CUDA source intent to PTX, final SASS, dynamic NCU behavior, and paired end-to-end latency.

Use case: scientific-educational

Asset type: Lesson 12 hero infographic for a Chinese GPU course

## 16:9 visual requirements

- Exact canvas: 1672×941 pixels, landscape 16:9.
- Dark navy engineering-blueprint background, cyan evidence path, amber compiler transformation, lime only for a closed provenance link.
- Crisp flat vector-like technical illustration, five large stations, wide spacing, large readable Chinese/English technical labels.
- A single binary fingerprint line must visually connect the final instruction artifact to the profiler observation.
- No code dump, tiny assembly, photorealism, people, logos, watermark, fake flame graph, or measurement number.

## Text (verbatim)

Main title:

“源码是意图，SASS 才是执行”

Short labels; render only these labels and no additional prose:

- “CUDA 源码”
- “PTX”
- “SASS”
- “NCU”
- “端到端时延”

## Core composition

Build one left-to-right five-station evidence chain.

Begin with a human-readable blueprint card labeled “CUDA 源码”. Feed it into an intermediate instruction sheet labeled “PTX”. Pass that sheet through one compiler gear into a compact machine-instruction strip labeled “SASS”. Stamp the SASS strip with an abstract B200-shaped chip seal and a unique fingerprint pattern, without adding model text or hashes. A magnifying glass labeled “NCU” observes hot instruction positions on that exact strip. The final arrow reaches a paired stopwatch labeled “端到端时延”.

Run one thin continuous fingerprint line from the SASS artifact through NCU to the stopwatch evidence bundle. The line means the measurements and disassembly must refer to the same binary. Make later stages visually more concrete than earlier stages.

## Misleading claims to avoid

- Do not portray PTX as the final instruction stream executed by the hardware.
- Do not claim that every `LDL` or `STL` instruction is necessarily register spill.
- Do not imply that the presence of a Tensor Core instruction means Tensor Cores are continuously busy.
- Do not let NCU kernel duration replace paired end-to-end timing as the final decision.
- Do not combine source, SASS, and measurements from different binaries.
- Do not add register counts, stack sizes, instruction counts, latency, speedup, percentage, or any invented number.
